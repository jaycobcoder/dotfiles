# 코드 품질

## 가독성

- 코드는 작성되는 것보다 훨씬 자주 읽힌다. 가독성을 최우선으로 한다.
- Master Service만 읽어도 전체 유즈케이스 흐름이 드러나야 한다.
- 암묵적 동작(이벤트, AOP 남용)보다 직접적인 메서드 호출을 선호한다.

## 복잡도

- 순환 복잡도는 **9 이하**를 권장한다.
- 가능한 한 9를 넘기지 않도록 하고, 불가피한 경우에만 용인한다.
- 복잡도를 낮추려고 과도한 추상화를 도입하는 것은 오히려 역효과다.

## 공통 로직 추출 기준

- private 메서드가 **3곳 이상에서** 사용되면 공통 컴포넌트(Processor 등)로 추출한다.
- 2곳 이하에서 사용되면 각 클래스 내부의 private 메서드로 유지한다.

## Javadoc 규칙

1. **유비쿼터스 언어로 작성한다.** 도메인 전문가와 개발자가 동일하게 이해하는 용어를 사용한다.
2. **인터페이스 Javadoc은 추상적으로 유지한다.** 구현 세부사항을 기술하지 않는다.
3. **HTML 닫는 태그(`</>`)를 작성하지 않는다.** `<p>`, `<li>` 등 여는 태그만 사용한다.

### 좋은 Javadoc 예시

```java
/**
 * 정액의 등지방두께에 따른 등급을 평가한다.
 * <p> 등지방두께는 값이 작을수록 좋다. 따라서 다른 Epd Value와는 달리, 등지방두께는 Epd Standard와 비교하는 조건식이 반대로 적용된다.
 *
 * @param backfat 정액의 등지방두께;
 * @return 등지방두께에 따른 등급;
 */
```

이 예시가 좋은 이유:
- 도메인 용어(정액, 등지방두께, Epd)를 그대로 사용하여 도메인 전문가도 읽을 수 있다.
- 의도와 함께 **왜 다르게 동작하는지**를 설명한다.
- 닫는 태그 없이 `<p>`를 사용한다.
